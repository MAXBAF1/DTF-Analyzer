# DTF Indie Analyzer roadmap

Цель проекта — постоянно мониторить тему [DTF Indie](https://dtf.ru/indie), измерять стартовую динамику каждого нового поста и помогать выбрать лучшее окно для публикации, в том числе для постов про Around.

## Как система работает сейчас

1. `monitor.py` запускает бесконечный цикл, опрашивает ленту с заданным интервалом и создает асинхронную задачу трекинга для новых постов.
2. `discover.py` читает актуальную ленту DTF `v2.10/timeline`, нормализует id, заголовок, дату публикации, автора, subsite-метаданные, URL и текущую позицию в ленте.
3. `tracker.py` на фиксированных чекпоинтах после публикации запрашивает `v2.10/content?id=...&markdown=false`, сохраняет просмотры, реакции, дочитывания, hits, online и вычисляет скорость/ускорение/ER.
4. `analyzer.py` уже умеет считать лучшие день/час публикации по историческим данным и простой live competition index как средние просмотры на `+10m` у последних 20 постов.

## Что нужно добавить для желаемого результата

### 1. Более плотные ранние замеры

Статус: реализовано базовое покрытие первой минуты через чекпоинты `+15s`, `+30s`, `+45s`, а затем `+1m`, `+2m`, `+5m`, `+10m` и далее. `minutes_since_publish` уже хранится как `REAL`, поэтому дополнительные секундные точки пишутся в существующую таблицу `metrics`.

Осталось улучшить:
- вынести набор чекпоинтов в конфиг или CLI-аргумент;
- отдельно выводить агрегаты `views_1m`, `views_10m`, `views_60m`;
- подобрать лимиты запросов, если DTF начнет ограничивать слишком частый polling.

### 2. История позиции в ленте

Статус: реализовано. Каждый опрос ленты теперь сохраняет видимые позиции в `feed_positions(post_id, ts, position, feed_page, snapshot_id)`, а чекпоинт метрики получает последнюю известную позицию на момент замера.

Осталось улучшить:
- добавить поддержку нескольких страниц ленты, если понадобится глубина больше текущего `count`;
- построить отчет зависимости просмотров от позиции `#1/#3/#10`;
- добавить очистку/архивацию очень старых feed snapshots, если база начнет быстро расти.
